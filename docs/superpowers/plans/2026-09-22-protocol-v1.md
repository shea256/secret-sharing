# Protocol v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Replace the unreleased SS2 hybrid implementation with a standard-library-only core implementing `PROTOCOL.md` v1, plus a separate `secretsharing-files` extension package, in one uv workspace.

**Architecture:** The core package (`packages/secretsharing`) implements byte-wise GF(2^8) Shamir, the v1 descriptor/payload/share layout, Base32 text encoding, a CLI, and explicit legacy v0 recovery, using only the standard library. The extension (`packages/secretsharing-files`) depends on the core plus `cryptography` and adds in-process age X25519 encryption for protection 2. Both packages test against shared vectors in `spec/vectors/`.

**Tech Stack:** Python 3.11+, uv workspace, pytest, hypothesis (dev only), `cryptography` (extension only). age 1.3.1 CLI used for interop tests when present.

**Spec:** `PROTOCOL.md` (wire format) and `.context/design-decisions.md` (decisions record).

## Global Constraints

- Core runtime dependencies: none. Only `secrets`, `hashlib`, `base64`, `struct`, `os`, `pathlib`, `argparse`, `getpass`, `json`, `subprocess`.
- Python `>=3.11`. Type hints on every signature. `ruff` clean.
- Package names on PyPI: `secretsharing` (core, existing name) and `secretsharing-files`.
- Wire constants exactly as `PROTOCOL.md`: domains `secretsharing/v1/{digest,check,id,sign}\x00`; descriptor head 25 bytes; payload `3 + capacity + 16`; checksum 4 bytes; text prefix `SS:V1:B32:`; filename `<id12>--share<NN>--<k>of<n>.ss.txt`.
- Limits: capacity ≤ 65535, shares ≤ 255, share text ≤ 262144 bytes.
- Secret bytes and share strings never appear in `repr`, exceptions, or logs.
- Recovery never consults filenames, profiles, or the extension. Unknown IDs are rejected. Signatures are never skipped silently.
- Commits on the current branch only; no push, no PR until Ryan asks.

## Review Focus

1. A share whose descriptor declares an `alg` the reader knows lengths for but cannot verify: default refuses; `allow_unverified=[alg]` recovers and labels. Test in Task 4.
2. Two shares with equal index but different `Y`: `DuplicateShare`, never counted. Test in Task 4.
3. Text share pasted with Windows line endings, lower case, and trailing spaces: decodes. `=` anywhere: rejected. Test in Task 3.
4. A 65,535-byte secret with threshold 255 and 255 shares: completes in seconds, not minutes, and round-trips. Test in Task 2 (field) and Task 4.
5. Protection 2 share where the ciphertext on disk does not match `file_hash`: `verify`/`combine --file` reports mismatch and writes no identity file. Test in Task 7.
